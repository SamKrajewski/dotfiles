# Model inversion: author detection and reviewer routing

Model families make different mistakes and share blind spots with their own
code, so a reviewer from a different family catches more. The talk claims
about 10% more bugs caught when author and reviewer families differ, that
Claude-written code skews to off-by-one errors, and that GPT-written code skews
to auth bypasses. These are vendor claims: the eval report splits catch rate
by `inverted` so you can check them on your own cases.

## Detection order

`scripts/detect_author.py` reads `tmp/change.json` and applies the table below
source by source. The first source with a hit decides; all hits are kept in
`signals` so the decision can be audited.

1. **Explicit:** a `--family` argument, `inversion.author_override` in
   config, a PR label `author-agent:<family>`, or an `Author-Agent:` trailer.
2. **Commit and PR text:** `Co-authored-by:` naming an agent, "Generated
   with" footers, agent email domains in trailers, Google-internal `TAG=agy`.
3. **Branch prefix:** `codex/`, `claude/`, `jules/`, and friends.
4. **Bot logins and emails:** the PR author login and commit author emails.
5. **Registry:** `inversion.registry` maps emails or logins to a family for
   teams that self-report.
6. Otherwise `unknown`. Code style is never used; a guess from style would
   route a human's code to the wrong pass and poison the evals.

The talk says fingerprints like these cover about 80% of agent-written PRs.
When the detector returns `unknown` for a PR you know an agent wrote, add the
signal to the table rather than guessing in the review.

## Routing

`detect_author.py` sets `route`, `inverted`, `reviewer_family` and
`reviewer_command`:

| Author | Reviewer (self) | Route | What step 5 does |
|---|---|---|---|
| human or unknown | any | `none` | Current model, no inversion. `inverted: false`. |
| agent family A | different family B | `cross-family` | Current model. `inverted: true`. |
| agent family A | same family A, another family's command configured | `inverted-cli` | Build the prompt file, run the command headless, parse its JSON as the draft. `inverted: true`. |
| agent family A | same family A, nothing else configured | `blind-spot` | Current model, then a second pass over the author family's weak classes. `inverted: false`. |
| agent family | `self_family` blank | `blind-spot` | Same as above; set `inversion.self_family` to get real routing. |

Set `inversion.self_family` to the family of the agent that runs this skill
(a Gemini-based host such as Jetski is `gemini`; Claude Code is `claude`;
Codex CLI is `gpt`).

## Headless reviewer contract

A reviewer command in `inversion.reviewers.<family>` receives
`{prompt_file}` (written by `scripts/build_prompt.py`, fully self-contained:
diff, intent, context pack, catalog, nitpick rules, explanation rules, schema)
and must write the draft JSON object from
`references/output.md` to `{out}`. Examples, to be adapted to the installed
CLI's flags:

```yaml
inversion:
  self_family: gemini
  reviewers:
    claude: 'claude -p "$(cat {prompt_file})" --output-format json > {out}'
    gpt:    'codex exec --json "$(cat {prompt_file})" > {out}'
```

If the command's output wraps the JSON (a transcript, a `result` field),
extract the object before validating with `review_report.py validate`. If
extraction fails, fall back to the blind-spot route and say so in
`coverage.not_checked`.
