# Workspace file formats

Normative reference for every file the skill reads or writes in the workspace.
`scripts/todo.py lint` enforces what is written here; its error codes are listed at
the end.

## Layout

```
<home>/                          default ~/todo, or $TODO_HOME
├── config.toml                  settings + which subskills run (see config.md)
├── TODO.md                      present state: goals, subgoals, tasks, priorities
├── log.md                       dated facts for the last few run-days
├── context.md                   standing facts and preferences (user-owned)
├── briefs/YYYY-MM-DD.md         one brief per run day (recent only)
├── drafts/YYYY-MM-DD/           material prepared for the user that day
├── subskills/<name>/SKILL.md    the user's own connectors
├── archive/                     old log months, briefs, drafts
└── .state/                      state.json, snapshot, backups, lock, runs.log
```

## The read path

A run reads `TODO.md`, `log.md`, `context.md` and the single most recent brief.
Nothing else in the workspace is read unless the user asks a question about the
past. Everything in this document is sized so that the read path stays small no
matter how long the skill has been running — that bound is what stops an old
mistake from being re-read into every future run.

## TODO.md

The present state, and only the present state. No history, no commentary. The user
may edit it by hand at any time, in any way; the next run adapts to their edits.

### Sections

Exactly these five `##` sections, in this order. Empty sections stay in the file.

| Section | Holds |
|---|---|
| `## Goals` | Active mainline goals (`###`), optional subgoals (`####`), and their tasks |
| `## Other tasks` | Active tasks that belong to no goal |
| `## Proposed` | Tasks the skill inferred and the user has not confirmed yet |
| `## Parked` | Goals and tasks deliberately on hold |
| `## Dismissed` | Source items the user rejected, remembered briefly so they are not proposed again |

### Example

```markdown
# TODO
<!-- Maintained by the todo skill. Edit freely: your edits always win. -->

## Goals

### G1 | Ship the Q4 billing migration | P1 | due: 2026-12-01
> Done when: all invoices are generated by the new system for one full cycle.
- [ ] T12 | P1 | Get finance sign-off on the cutover date | due: 2026-11-13 | next: send the reply to Dana | draft: drafts/2026-11-11/T12-reply-dana.md | src: gmail "Cutover date?" 2026-11-10
- [ ] T13 | P2 | Write the rollback runbook | next: outline section 3 | src: user
  - [ ] T17 | P2 | List the tables the rollback touches | src: user

#### G1.1 | Data backfill | P2
- [ ] T14 | P2 | Dry-run the backfill on staging | waiting: Priya since 2026-11-07 | nudge: 2026-11-12 | src: gdocs-meeting-notes "Weekly sync" 2026-11-06

### G2 | Hire a second backend engineer | P2
- [ ] T16 | P1! | Send feedback on the two onsite candidates | due: 2026-11-12 | src: user

## Other tasks
- [ ] T20 | P3 | Renew passport | due: 2027-01-15 | src: user

## Proposed
- [ ] T21 | P2? | Send Q3 metrics to Alex | src: gdocs-meeting-notes "Weekly sync" 2026-11-06 | proposed: 2026-11-11

## Parked
- [ ] T8 | P3 | Evaluate the new CI provider | parked: 2026-11-02 | src: user

## Dismissed
- gmail "Team offsite survey" 2026-11-08 | dismissed: 2026-11-11 | why: not mine
```

### Goals and subgoals

```
### G<n> | <title> | P<0-3>[!] [| due: YYYY-MM-DD]
> Done when: <one line>                      optional, at most one line, ≤ 200 chars
#### G<n>.<m> | <title> [| P<0-3>[!]] [| due: YYYY-MM-DD]
```

- A goal is a mainline outcome that takes more than a few tasks. Keep the list short;
  five active goals is already a lot.
- Add a subgoal only when a goal has grown distinct workstreams. Most goals need none.
- A subgoal without its own priority inherits the goal's.
- Goals may also sit under `## Parked`, with the same syntax, carrying their tasks.

### Tasks

```
- [ ] T<n> | P<0-3>[!|?] | <title> [| key: value]...
```

- One line per task, at most 300 characters. The separator is ` | ` (space, pipe,
  space); a title cannot contain it.
- A task may have sub-tasks: full task lines indented by two spaces, one level deep.
  Use them only when the parent cannot be finished in one sitting.
- Checkbox: `[ ]` open. `[x]` (done) and `[-]` (dropped) are how the *user* signals a
  change by hand; the next run logs it and removes the line, so neither survives a run.

Fields, all `key: value`:

| Key | Meaning |
|---|---|
| `src` | **Required.** Where the task came from: `user`, or `<subskill> "<label>" <date>`, or a URL. This is what lets a wrong task be traced and checked. |
| `due` | Hard date, `YYYY-MM-DD`. Only real deadlines; do not invent one. |
| `next` | The single next concrete action. Overwritten when it changes, never appended to. |
| `waiting` | Who or what the task is blocked on, e.g. `Priya since 2026-11-07`. |
| `nudge` | `YYYY-MM-DD` on which to follow up on a `waiting` task. |
| `draft` | Workspace-relative path to material prepared for this task. Removed once used or obsolete. |
| `note` | One short clause, only when the title cannot carry it. |
| `proposed` | `YYYY-MM-DD` the task was proposed. Required in `## Proposed`, nowhere else. |
| `parked` | `YYYY-MM-DD` the item was parked. Used in `## Parked`. |

Dates are always full ISO dates. Recommended field order: `due`, `next`, `waiting`,
`nudge`, `draft`, `note`, `src`, then `proposed`/`parked`.

### Priorities

| Level | Meaning |
|---|---|
| `P0` | Must happen today: a deadline today or already missed, or others are blocked right now |
| `P1` | Important this week: due within about seven days, someone is waiting on the user, or it directly moves a P1 goal |
| `P2` | Should be done; no near deadline |
| `P3` | Nice to have |

- `P1!` — pinned by the user. The skill never changes a pinned priority; it may suggest
  a change in the brief.
- `P2?` — provisional guess, used only in `## Proposed`.

### Ids

`T<n>` for tasks, `G<n>` for goals, `G<n>.<m>` for subgoals. Ids are never reused and
never renumbered: the log and the briefs refer to them. New ids come from `next_id` in
the output of `todo.py begin`.

### Dismissed

```
- <source reference> | dismissed: YYYY-MM-DD | why: <short reason>
```

Written when the user rejects a proposal or says an item is not theirs, and when a
proposal expires unanswered (`why: expired unanswered`). The reference is the `src`
of the rejected item. `todo.py finish` deletes entries older than
`intake.dismissed_keep_days`.

### What the user may type by hand

Anything. A line such as `- call the dentist` under any section is fine: the next run
turns it into a proper task line (new id, a priority, `src: user`) and keeps the
wording. The strict format only has to hold when a run *finishes*.

## log.md

Dated facts, newest first. This is the skill's only memory of the past, so it is kept
deliberately small and deliberately dull.

```markdown
# Log
<!-- Dated facts only, newest first. Older entries move to archive/ and are not read. -->

## 2026-11-11 Wed
- done: T9 Send contract to legal; T11 Book dentist
- progress: T13 outline drafted
- added: T22 Prepare offsite agenda (google-calendar); T21 proposed (gdocs-meeting-notes)
- changed: T12 P2→P1 (due in 2 days)
- dropped: T7 Evaluate CI provider (user)
- corrected: T15 is waiting on Priya, not Dana (user)
- prepared: T12 reply draft; T18 flight details
- sources: google-calendar ok; gmail ok; gdocs-meeting-notes failed (not authenticated)

## 2026-11-10 Tue
- done: T5 Submit expense report
- sources: google-calendar ok; gmail ok; gdocs-meeting-notes ok
```

Rules:

- One entry per day on which anything happened: `## YYYY-MM-DD Ddd` (`Mon`…`Sun`),
  strictly newest first. A second run or a quick update on the same day merges into
  that day's entry.
- Each bullet is `- <verb>: <items>`, items separated by `; `, at most 500 characters.
  One bullet per verb per entry.

| Verb | Records |
|---|---|
| `done` | Tasks completed — id and title. The title is required here and under `dropped`: it is how an item that a source reports again is recognised as already closed. |
| `progress` | Tasks that visibly moved without finishing |
| `added` | New tasks and proposals, with where they came from |
| `changed` | Priority, due date, goal membership, parked/unparked, proposal accepted |
| `dropped` | Tasks removed without being done, with who decided; expired or rejected proposals |
| `corrected` | A wrong fact that was replaced, stated as the *right* fact, plus who corrected it |
| `prepared` | Drafts and lookups produced |
| `sources` | Status of every subskill that ran (daily runs only) |
| `note` | A dated fact that fits nothing above. Rare. |

- Every task id that has appeared in or disappeared from `TODO.md` since the skill
  last finished must be mentioned in that day's entry, whether the run made the change
  or the user did it by hand (`todo.py finish` checks this). This is what makes the
  log a complete record, and it is how staleness is measured.
- Never edit, merge or summarise an older entry. `todo.py finish` keeps the newest
  `history.log_keep_days` entries and appends older ones to `archive/log-YYYY-MM.md`.
- No reasoning, plans, or guesses. If it is not a fact with a date, it does not belong.

## briefs/YYYY-MM-DD.md

What the user reads in the morning. A second run on the same day rewrites the file.

```markdown
# Daily brief | 2026-11-11 Wed

## Focus today
1. **T12** Get finance sign-off on the cutover date (P1, due Fri) — next: send the reply to Dana; draft ready
2. **T16** Send feedback on the two onsite candidates (P1, due tomorrow)
3. **T13** Write the rollback runbook (P2) — next: outline section 3

## Schedule
- 10:00–10:30 Weekly sync — bring T13 status
- 14:00–15:00 Onsite debrief — feeds T16

## Since last run
Tue 2026-11-10 → now
- Done: T9 Send contract to legal; T11 Book dentist
- Progress: T13 outline drafted
- No visible progress: T12 (in focus yesterday)
- New: T22 Prepare offsite agenda (from calendar)

## Needs your input
- Accept or reject: T21 "Send Q3 metrics to Alex" (gdocs-meeting-notes "Weekly sync" 2026-11-06)
- T7 has had no activity for 5 run-days: keep, park, or drop?
- I can also draft the offsite agenda for T22 if you want it.

## Prepared for you
- drafts/2026-11-11/T12-reply-dana.md — reply to Dana with the cutover date. Check the freeze length before sending.
- T18 flight: UA 123, Thu 2026-11-12 08:05 EWR→SFO, confirmation ABC123 (gmail "Your trip" 2026-11-02)

## Follow-ups due
- T14 waiting on Priya since 2026-11-07 — nudge drafted: drafts/2026-11-11/T14-nudge-priya.md

## FYI
- Office closed Fri 2026-11-27 (gmail "Holiday schedule")

## Sources
- google-calendar ok (6 events); gmail ok (37 scanned, 4 actionable); gdocs-meeting-notes FAILED: not authenticated (2nd run in a row)
```

- First line: `# Daily brief | YYYY-MM-DD Ddd`.
- Required sections, in this order: `## Focus today`, `## Since last run`,
  `## Needs your input`, `## Prepared for you`, `## Sources`. Write `Nothing.` under a
  required section with no content.
- Optional sections, placed as in the example: `## Schedule`, `## Follow-ups due`,
  `## FYI`. Leave them out when empty.
- Aim for one screen; 100 lines is the ceiling. `## FYI` holds at most five items.
- `todo.py finish` keeps the newest `history.brief_keep_days` briefs and moves the
  rest to `archive/briefs/`.

## drafts/

`drafts/YYYY-MM-DD/<task-id>-<slug>.md`, one file per prepared item, starting with a
short header:

```markdown
---
for: T12
kind: email-reply          # email | email-reply | message | agenda | summary | lookup | notes | other
to: Dana Kim
subject: Re: Cutover date?
basis:
  - Dana asked for the date by Fri 2026-11-13 (gmail "Cutover date?" 2026-11-10)
  - Cutover target is 2026-12-01 (TODO.md G1)
open:
  - "[[confirm: length of the finance freeze]]"
---

Hi Dana, …
```

- `basis` lists the facts the draft relies on, each with its source, so the user can
  verify it in seconds.
- `open` lists every `[[placeholder]]` left in the body. A fact that is not known is
  left as a placeholder — never filled with a plausible guess.
- Draft directories are archived together with their brief, except those still
  referenced by a `draft:` field in `TODO.md`.

## context.md

Standing facts and preferences that make every run better: who people are, working
hours, what kinds of items never matter. At most 40 non-blank lines.

```markdown
# Context
<!-- Standing facts and preferences. Yours: the skill only changes this file when you ask it to. -->

## People
- Dana Kim — finance lead; approves anything touching invoicing

## Preferences
- No more than three focus items on days with four or more hours of meetings
- Newsletters and automated notifications are never tasks
```

This file belongs to the user. The skill changes it only on the user's explicit
request in an interactive session, and never during an unattended run — a durable
note that is wrong would be re-read forever.

## Lint codes

`todo.py lint` prints `file:line: CODE message`. Errors (`E`) block `finish`; warnings
(`W`) do not.

| Code | File | Rule |
|---|---|---|
| E101 | TODO.md | The five `##` sections are missing, repeated, misordered, or an unknown `##` section exists |
| E102 | TODO.md | Malformed goal or subgoal heading; subgoal not under its parent goal; goal heading outside `## Goals`/`## Parked` |
| E103 | TODO.md | Malformed task line, checkbox other than `[ ]` `[x]` `[-]`, indentation other than 0 or 2 spaces, sub-task without a parent |
| E104 | TODO.md | Duplicate `T` or `G` id |
| E105 | TODO.md | Unknown field key |
| E106 | TODO.md | Invalid date in `due`, `nudge`, `proposed`, `parked`, `dismissed` |
| E107 | TODO.md | Task without `src` |
| E108 | TODO.md | Line longer than 300 characters |
| E109 | TODO.md | `?` priority outside `## Proposed`; proposed task without `?` or without `proposed:` |
| E110 | TODO.md | Task still marked `[x]` or `[-]` — log it and remove the line |
| E111 | TODO.md | Unrecognised line (free-form text that was not turned into a task line) |
| E112 | TODO.md | Malformed `## Dismissed` line |
| W120 | TODO.md | More than 15 proposals |
| W121 | TODO.md | More than 60 open tasks |
| W122 | TODO.md | `draft:` points to a file that does not exist |
| W123 | TODO.md | Active goal with no open task |
| W124 | TODO.md | Id at or above the `next_id` counter, i.e. typed by hand. Reported outside a run only; `begin` already hands out ids above it. |
| E201 | log.md | Malformed entry heading, weekday not matching the date, entries not strictly newest-first |
| E202 | log.md | Bullet is not `- <verb>: <text>` with a known verb |
| E203 | log.md | The same verb twice in one entry |
| E204 | log.md | Bullet longer than 500 characters |
| E205 | log.md | A `done` or `dropped` item names a task id without its title |
| W210 | log.md | More entries than `history.log_keep_days` (trimmed at `finish`) |
| E301 | finish | A task id that was in `TODO.md` when the skill last finished (or when this run began) is gone, and today's log entry does not mention it |
| E302 | finish | A task id is new since the skill last finished (before the first finished run: since this run began), and today's log entry does not mention it |
| E303 | finish | Daily run finished without today's brief |
| E401 | brief | First line is not `# Daily brief | YYYY-MM-DD Ddd` for today |
| E402 | brief | A required section is missing or out of order |
| W410 | brief | Longer than 100 lines |
| W501 | context.md | More than 40 non-blank lines |
